Build: The map-position reader can no longer cost you the page

Test Focus: Reading a map's position means running a small script on every page you visit. That
script once broke real sites — they came up blank. This build makes that impossible to ship again:
there is now a switch you can turn off, and the app stops by itself on a site it appears to have
broken. Nothing about how coordinates are read has changed, so the first thing to check is that
everything still works exactly as before.

- Browse normally for a while first: follow links, go back and forward, sign in somewhere, visit a
  site whose address starts http:// and upgrades itself to https://. Everything must behave exactly
  as it did before. This build changes how pages are loaded, so ordinary browsing is the most
  important thing to try.

- Save a finding on https://www.freemap.sk/#map=15/47.941230/18.709545 — the GPS field should fill
  in by itself, starting with "leaflet:". Do the same on
  https://caltopo.com/map.html#ll=38.97469,-100.06486&z=12 and on
  https://openlayers.org/en/latest/examples/simple.html, which should show a coordinate starting
  "Web Mercator".

- Open americanamap.org, openlayers.org and basemap.at. Each must draw its map normally. These three
  are the sites that went blank while this feature was being built, so they are the ones that
  matter.

- Go to Settings, Web content. There is a new switch, "Read map position from pages", and it is on.
  Turn it OFF. Now open a map page — you must load a page after flipping the switch, because it
  applies to the next page you open, not the one already on screen. Save a finding on freemap.sk or
  openlayers.org: the GPS field must stay EMPTY, and the Page field must still show the address.
  Losing the coordinate is the point; losing the address would be a bug.

  One thing that is NOT a bug: on a site whose address itself carries coordinates — for example
  zbgis.skgeodesy.sk/mapka/en/teren?pos=48.800000,19.530000,12 — you will still see a GPS value
  beginning "url:" with the switch off. That is read from the address the app already has, not from
  the page, so it cannot cost you the page and is deliberately left working. The switch turns off
  only what touches the page: values beginning "leaflet:", "arcgis:", "maplibre:" or "shown:".

- Turn the switch back ON, open a map page again, and confirm coordinates come back.

- In Settings, Reset: the switch must return to on afterwards.

- If you ever meet a map page that comes up blank, watch what happens next: the app should reload it
  once by itself, and the page should then work — with no coordinate on that site for the rest of
  the session. It must not reload over and over, and it must never reload a page that was fine.
  This is hard to provoke deliberately; report it if you see it happen at the wrong moment.
