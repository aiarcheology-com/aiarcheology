Build: The page address saved with a finding

Test Focus: The Save Finding form now explains what the Page address can and cannot do, and shows
it at a readable size. Nothing about what gets captured or stored has changed in this build.

- Save a finding on any map site. Under the Page field there is now a note: the address may be
  fixed and may not carry the position you captured, so open it once to check where it lands and
  fall back to the GPS position below if it is wrong. Please say whether that reads clearly, and
  whether it still looks right at the largest text sizes (Settings > Accessibility > Display & Text
  Size > Larger Text, with "Larger Accessibility Sizes" on).

- The URL in the Page field is now the same size as the GPS value below it, instead of noticeably
  smaller. Check a long address still fits sensibly and can be read and corrected comfortably.

- Reported case worth reproducing: on geoland.at the saved address carries no position at all, so
  reopening it shows the whole of Austria while the GPS value is correct. That is the situation the
  new note is there to explain — confirm it now makes sense rather than looking like a bug.

STILL WORTH RETESTING FROM THE PREVIOUS BUILD

- Aiming a finding: tap Find, then the large crosshair in the middle of the web content. RED stores
  the place under it, GREEN stores a detected rectangle covering it. Only a small area in the very
  middle takes the tap; everywhere else must still pan and pinch-zoom normally.

- KNOWN GAP, please test specifically: on a map site that writes its own position into the address
  bar (atlas.bayern.de), the protection against us overwriting that address only engages once the
  app has seen the site update it. If you reopen the app straight onto such a page (Reopen Last
  Page) and save a finding WITHOUT panning first, the address may still be wrong. Please report
  whether that reproduces — it decides whether a further fix is needed.
