Test Focus: Stability + Sentry event throttling guardrails
Build: TBD

This build adds client-side protection against runaway error loops that could spam Sentry events. Normal app logging should be unaffected.

Devices / Platforms
- iPhone (required)
- iPad (if available)

1. Core Regression
- Browse a few websites and confirm the web view loads as expected.
- Run object detection and verify annotations appear and update normally.
- Switch models/configurations and verify detection still works.

2. Sentry Guardrails (QA)
- If you can see it: Settings → Debug → "Sentry Stats"
  * Confirm counters update while using the app.
  * During error bursts, events should be limited and drop counters should increase (duplicate/global/session).

3. Crash / Error Reporting
- If you hit a repeated error (e.g., a failing loop), the app should remain responsive.
- Please report any crashes or broken flows with:
  * What you did (steps)
  * Approximate time
  * Screenshot if possible
