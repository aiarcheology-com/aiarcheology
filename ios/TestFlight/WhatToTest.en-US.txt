Test Focus: Finding save path refactor (AIA-0392) — no visible change expected
Build: TBD

What's new in this build:
Internal restructuring only. The code that saves a finding (writes the screenshot, creates the
database record, and validates it) was moved out of the save screen into one dedicated, auditable
component. There is NO user-facing change. This build is a regression check that capturing and
saving findings — and the failure/rollback behavior — work exactly as before.

1. Capture & save a finding
- Run a detection demo, tap Find/Store, tap the content to capture a detection.
- In the save sheet: adjust the crop (pinch/drag or the zoom slider), type a Title (Save stays
  disabled until the title is non-empty), optionally add a label/note/GPS, then tap Save.
- The sheet dismisses and the finding is saved.

2. Verify it persisted
- Open the drawer → Findings. The finding you just saved appears, with its cropped screenshot and
  the details you entered.

3. Crop is honored
- Save a finding with a tight crop; in Findings its screenshot should be the cropped region (the
  highlight box still lines up).

4. Cancel path
- Start a capture, then dismiss the save sheet without saving — nothing is added to Findings, and
  the app returns to browsing normally.

5. Onboarding tour (save step)
- Replay onboarding from Settings and follow it through the "save a finding" step — saving still
  advances the tour correctly.

6. Report Issues
Please report any issues with:
  * What you were doing (steps to reproduce)
  * Device model and iOS version
  * Screenshot or screen recording if possible
