Test Focus: Detection/classification pipeline internals refactor (AIA-0387) — no visible change expected
Build: TBD

What's new in this build:
Under the hood, the code that runs detection and classification models was moved off
the main thread into a dedicated background engine, so a busy model can no longer stutter
scrolling or tapping. There is NO intended change to what you see — this build is a
regression check: everything that worked before must still work, exactly the same.

1. Detection still works (boxes)
- Run the built-in detection demos: bounding boxes should appear over recognized content
  and clear when it leaves the screen, exactly as before.
- Save a finding from a detected box: it should capture and persist as usual.

2. Classification finding-flash still works
- Import/enable a classification model (side menu → + → import a .mlmodel by URL or file),
  then browse a normal page with detection on: the frame should still pulse with the soft
  colored border when the model recognizes the content.
- With Settings → Show Labels ON, the top-right bubble should still list matches + percentages.

3. Stress the live pipeline (the point of this change)
- While a model is actively running, scroll fast, rotate the device, and pinch-zoom:
  boxes/flash should pause during interaction and resume cleanly after the page settles —
  no frozen boxes, no stuck pulse, no stale label bubble, no lag or hangs.
- Enter and leave a saved finding, switch models on/off mid-session, and background/foreground
  the app while detection is running: the pipeline should keep up and never leak an old result
  onto the new screen.

4. Report Issues
Please report any issues with:
  * What you were doing (steps to reproduce)
  * Device model and iOS version
  * Screenshot or screen recording if possible
