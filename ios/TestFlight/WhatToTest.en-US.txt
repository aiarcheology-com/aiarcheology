Test Focus: Detection/chrome state split (AIA-0391) — no visible change expected
Build: TBD

What's new in this build:
Internal restructuring only. The single "Guide" object that mixed the detection-session controls
with the browser-chrome state was split into two focused objects (one owns the on-the-fly detection
lifecycle and the snapshot timer; the other owns the drawer/tab chrome and page navigation). There
is NO user-facing change. This build is a regression check that detection, the fullscreen chrome
behavior, tab switching, the drawer, settings, the onboarding tour, and background/foreground
behave exactly as before.

1. Detection start/stop & fullscreen chrome
- Enable a model and start on-the-fly detection. Bounding boxes / labels appear and update.
- With "Fullscreen detection" on in Settings: starting detection hides the browser chrome; the
  floating chrome-toggle button appears; tapping it reveals/hides the chrome without stopping
  detection. Stopping detection restores the chrome every time.

2. Tab / mode switching & drawer
- Switch between the app's tabs/modes; the tab bar and navigation behave as before.
- Open and close the side drawer; open a page from the drawer — it loads.

3. Settings
- Open Settings. Toggle "Fullscreen detection" and change the snapshot "Frequency" while detection
  is running — the running detection updates accordingly, no crash. "Restore defaults" stops any
  running detection and resets the app.

4. Finding capture
- While detecting, tap Find/Store and save a finding. The snapshot pauses during the save dialog
  and resumes afterward (if detection was running).

5. Background / foreground
- Start detection, background the app, return — detection auto-pause/resume behaves as before.

6. Onboarding tour
- Replay onboarding from Settings (or first launch). The spotlight steps that start detection and
  enter pick-mode still advance correctly.

7. Report Issues
Please report any issues with:
  * What you were doing (steps to reproduce)
  * Device model and iOS version
  * Screenshot or screen recording if possible
