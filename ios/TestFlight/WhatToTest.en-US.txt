What's new in this build:
The on-screen detection logic (which frames get detected, when boxes clear, and how the
save-a-finding freeze works) was moved out of the view into a new internal coordinator. There
is NO intended change to what you see — this build is a regression check that the detection
overlay still behaves exactly as before.

1. Boxes appear, update, and clear
- Run a detection demo and browse: bounding boxes should appear over recognized content, keep
  up as the page updates, and clear when content leaves the screen — no lag, no stale boxes.

2. Scroll / pinch-zoom clears immediately, then re-detects
- While scrolling or zooming, boxes should clear at once (geometry is changing). When the
  content settles, boxes should re-appear correctly aligned. Repeat quickly a few times — no
  boxes should ever be left behind in the wrong place.

3. Rotate / show-hide chrome re-aligns
- Rotate the device or toggle the toolbars while boxes are shown: the old boxes should clear
  and fresh ones should appear aligned to the new layout.

4. Save a finding keeps the frame frozen
- Tap to pick/save a finding: while the capture/save sheet is up, the boxes underneath must
  stay exactly as they were (frozen) — they must not flicker, move, or get replaced by a new
  detection pass. After you save or cancel, detection should resume normally. Exercise this a
  few times, including cancelling.

5. Classification finding-flash still works
- With a classification model enabled, the pulsing frame flash and label bubble should still
  appear on recognized content, and stop when you pause detection or start interacting
  (unchanged).

6. Report Issues
Please report any issues with:
  * What you were doing (steps to reproduce)
  * Device model and iOS version
  * Screenshot or screen recording if possible
