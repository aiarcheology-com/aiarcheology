Build: A findings export can always be brought back in

Test Focus: Findings → Data lets you export every finding as a zip and import it back. That file is
the safety net the app offers right before "Remove all findings" — and for a large collection it
did not work: the export succeeded, and importing the same file was refused as "not a findings
archive". This build fixes that. An import is now limited by the free space on the device — and by
a ceiling of about four thousand findings per file — and by nothing else.
Separately, if the app's private sync record ever got damaged, backing up used to quietly switch
itself back ON; it now switches OFF and stays off until you turn it on yourself.

- The round trip. Open Findings, tap Data → Export, and save the zip to Files. Then Data → Import
  and pick that same file. You get a question about duplicates — choose Replace. Every finding must
  still be there, each with its picture, exactly as before. Then import once more and choose Keep:
  the summary should say 0 restored and all skipped. Import a third time and Cancel: nothing changes.

- The case that was broken. If you have a large collection — dozens of findings, especially ones
  saved on an older version of the app, whose pictures are bigger — export it and import it back. On
  the previous build that file was refused. It must import now, with the counts matching. While it
  runs, the Data button becomes a spinner; that is expected, and the list fills in when it finishes.

- Nearly full device. If your phone is very low on space, importing a large file refuses up front
  with an error rather than filling the phone. Freeing space and trying again should work.

- Back-up switch. In Settings, turn "back up my findings" OFF. Use the app normally for a while —
  background it, sign out and in, restart it. The switch must stay OFF. If you ever find it has
  turned itself back on without you, that is a bug — please report exactly what you did before.

- Deleting while signed out. Sign out, delete a finding that was backed up, then sign back in and
  let the app sync. The deleted finding must NOT come back.

- Killing the app mid-import. Start importing a large archive and force-quit the app while the
  Data button is a spinner. Reopen, import again and let it finish. This build no longer leaves the
  interrupted attempt's copy of the archive behind — there is nothing you can see for this, but if
  you have a way to check the app's storage in Settings, it should not have grown by the size of
  the archive per kill.

- Two count lines under the sync status now read correctly in every language for 1, 2–4 and 5+
  findings — e.g. "1 konnte nicht gesichert werden" versus "3 konnten…" in German. Worth a glance
  if your device is set to German, French, Czech, Polish, Russian or Ukrainian.
