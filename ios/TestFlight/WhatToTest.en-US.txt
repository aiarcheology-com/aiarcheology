Build: Importing an already-compiled Core ML model

Test Focus: Core ML models come in two shapes. The ones you usually download — .mlmodel and
.mlpackage — are source models the app compiles on your device when you import them. A folder named
something.mlmodelc is a model that has ALREADY been compiled (Xcode produces these). The app has
always listed .mlmodelc as supported, but importing one failed, because it tried to compile it a
second time. This build loads a compiled model as-is. Nothing about importing .mlmodel or .mlpackage
files, or about the built-in demo models, should change.

- Get a compiled model onto the phone. It must be compiled FOR iPhone: take the .mlmodelc that an
  Xcode iOS build wrote next to the app (in the Products folder of the build), or ask the team for
  one. Put it in iCloud Drive or AirDrop it so it shows up in Files. A .mlmodelc compiled on a Mac
  for the Mac is NOT expected to work — see the last point.

- Import it. Models → Import → Files, and choose the .mlmodelc. It should appear as a single item you
  can pick, not as a folder you can only open. If Files only lets you browse into it, stop there and
  report that — it is the one part of this we could not check without a phone.

- The import must finish and the new model must show its details (name, type, author or version
  where the model has them) like any other imported model. Enable it and point the camera at
  something it should recognise: it must run. Turn it off and on again; force-quit the app, reopen
  it, and confirm the model is still there and still runs. Then delete it — that must work as it
  does for any imported model.

- The usual path is unchanged. Import a normal .mlmodel or .mlpackage the way you always have; it
  must still compile and run exactly as before. The built-in demo models must still work.

- The expected failure. If you import a .mlmodelc that was compiled for a different platform (a Mac
  build), or a folder that is only named .mlmodelc, the import must fail with a message that says
  the compiled model could not be loaded on this device and that compiled models are
  platform-specific — and the app must stay usable afterwards. A crash, a hang, or a message that
  says nothing about why is a bug.
